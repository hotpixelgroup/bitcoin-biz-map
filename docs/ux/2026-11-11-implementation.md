This release implements the software work across the ten areas in the [repo-wide review](2026-11-11-review-and-plan.md). The catalog retains all 9,452 listings and existing IDs.

## Data ownership and release

`dist/merchants.json` remains canonical. Packaging emits `.publish/` with a SHA-derived catalog revision, index, state details, full export and generated pages. The static page evidence view also takes a UTC build date (`BUILD_DATE=YYYY-MM-DD` makes that input reproducible). Generated output is ignored by Git. The automated reviewer still changes only the canonical catalog; deployment regenerates every public representation together. The legacy `merchants.json` path and hash links remain available.

Exact origins never enter storage, collection exports or public share links. Drafts exist only in page memory. Offline storage requires an explicit action and contains public data only. Receipt status has a separate random lookup token, bounded retention/rate limits, a no-referrer page and no report-body endpoint. The Worker uses the existing D1 table and shared secret; no migration or additional service is required.

The complete local check passes: **65 Node tests**, Python import regression fixtures, every catalog row, packaging and the served Pages-subpath smoke test. Wrangler bundles the Worker successfully; the pinned Wrangler update removes the previously reported development dependency vulnerabilities. The actual PR check and deployment results belong to the PR/Actions records.

The review's November 11 baseline had 177 community records older than 365 days. The operational report evaluates its own UTC date; at November 12 UTC it reports 238 recheck candidates. These are source-age labels, not new negative payment reports. No national source refresh was performed merely to make old dates look current.

Physical iPhone/Android, VoiceOver/NVDA, actual device keyboard/browser chrome, real network field performance and real-user satisfaction are **not measured by these automated or desktop-browser checks**. The stylesheet still uses the existing base/responsive files plus the shared component layer; this is an incremental consolidation, not a rewritten design framework. No new analytics or persistent user identifiers were added.

## User happiness validation protocol

Recruit first-time Bitcoin spenders, returning local users, travelers and maintainers; include assistive-technology users. Run the same tasks on a baseline build and this build with order counterbalanced. Use synthetic report text and stop before any public submission. Record anonymous session IDs only, with explicit participant consent; do not record exact GPS, wallets or personal form content.

| Task | Observe | Initial target, not an achieved result |
| --- | --- | --- |
| Find coffee in Chicago | Time to a relevant selected place; filter confusion | Median at most 20 seconds |
| Assess an old-source listing | Can the person distinguish source check, visitor report and unknown? | 8/10 correct without coaching |
| Recover after location denial | Choose a city/ZIP and get directions | 9/10 complete the core task |
| Recover a saved place and an accidental removal | Context retained; undo found; keyboard focus useful | No lost collection or blocked task |
| Report a payment problem and interpret its receipt | Draft recovery, completion time and status meaning | Median at most 30 seconds excluding evidence investigation |

Ask one optional 1–7 task-ease question after each task; target median 6 after establishing the baseline. Log concrete failures and revisit the corresponding implementation before making a satisfaction or competitive-superiority claim. Check 200% text/zoom, reduced motion, short landscape and the full journeys on physical Safari/Chrome and VoiceOver/NVDA. The owner must supply participants and nominate a backup maintainer; software cannot establish either by inference. The operational report supports twice-weekly triage, with closures/payment difficulties ahead of new additions.
